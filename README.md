# 项目测算分析工具

面向财务人员的本地项目测算与报表工具。当前已完成 Schema v14 最新结果与事实调整链路：财务人员可以在同一项目中维护多个独立方案，计算最新原始底稿，在计算底稿中保存人工调整，并通过项目报告和多维项目报表查看最终结果。

当前软件版本：`v0.5.6`。版本号唯一维护在 `src/package.json`；后续新增或调整功能时递增第三位版本号，例如 `v0.5.7`、`v0.5.8`。

## 当前能力

- React + TypeScript + Vite 单包工程。
- 正式运行采用本地 TypeScript 服务：浏览器界面只调用同源语义化业务接口，SQL、仓储和事务全部位于服务端，并实时同步到可见的 `data/amoya_project_forecast.db`。
- `.db` 是标准 SQLite 文件，可备份、恢复并使用常规 SQLite 工具检查。
- 旧单 HTML 仅作为兼容构建保留，使用内存 SQLite，不再作为日常入口。
- 真实部门新增、修改、启用和停用。
- 真实项目新增、修改、归档和恢复；项目主信息只保留项目编码、项目名称和申报部门，项目是唯一主表，不维护同步副本。
- 场景固定为全局“基准场景”；Plan 从属于项目，每个项目至少保留一个有效方案，可空白新建、复制、重命名、归档和恢复；未指定方案时稳定进入排序最前的有效方案。
- 页面主数据提供 2024-01 至 2030-12 的常用期间；数据库保留更宽的期间底座，以支持经营期后的现金回收尾期。
- 六份历史交付材料已逐份核对：其中 5 份形成可追溯参考项目，1 份 CDN/广告敏感性模型保留为后续分析模块需求。
- 五个历史项目均保存通用预测配置，并由同一计算服务生成事实和报表；不再直接灌入近似结构验证结果。
- 基础指标与系统计算指标统一管理。
- 项目内“项目配置—计算工作表—项目报告”三步工作区，并使用可刷新、可收藏的正式 URL。
- 三步工作区共享方案切换栏，各 Plan 的期间、参数、预测行、现金规则、人工调整和最终事实互相隔离。
- 项目列表下提供“项目报表”只读事实视图，可将项目、Plan、部门、期间和指标放入 POV、行轴或列轴，并为行列维度选择成员范围。
- 收入、成本、收款、付款行自动映射基础指标，财务人员无需维护指标编码。
- 项目信息在项目配置页以只读卡片呈现，点击编辑后原位维护；项目中心不再提供重复编辑入口。
- 开始期间和结束期间属于项目信息，数据库直接保存两端期间；月数由界面动态计算，不单独存储。
- 业务参数、损益测算和直接现金流共用统一行项目结构；公共字段单列保存，差异配置统一保存为 `config_json`，逐月值独立保存。
- 配置草稿使用与正式计算相同的共享引擎实时生成分月预览；保存只持久化配置，计算成功后才替换当前方案最新原始事实。
- 固定月金额和逐月填写两种首批预测方式。
- 项目固定参数和逐月参数，支持金额、数量、比例和普通数值。
- 行项目公式支持四则运算、参数引用、其他行项目引用和循环依赖检查。
- 损益行支持未税、含税和免税口径，公式引用统一读取标准化后的未税金额。
- 收付款规则支持当月、延后和自定义分期，以含税结算金额生成现金计划。
- 自动现金和直接现金分别追溯并汇总到统一事实。
- 现金尾期允许延伸到经营期后 36 个月，报表自动标记回收期。
- 项目配置页使用“保存”和“计算”；计算会先保存未保存修改，再事务化替换当前方案最新原始结果。
- 项目草稿使用乐观修订号；两个浏览器页面发生冲突时返回 409，不静默覆盖。
- 计算底稿支持矩形框选、TSV 复制粘贴、清空、撤销重做和叶子行人工调整。
- 人工调整独立保存在事实调整表，不回写项目配置，不参与预测项公式、税额或自动现金计划；保存调整后立即更新最终事实和派生指标，无需再次计算。
- 每个 Plan 只保留最新原始结果、最终事实和一条计算状态；前台不再显示或切换 Run 历史。
- 配置修改后，计算底稿继续显示上一版成功结果并明确提示需要重新计算。
- 真实项目没有事实时显示明确空状态。
- SQLite 数据库完整备份和恢复。
- 正式项目报告包含本地 ECharts 图表、确定性测算摘要、关键假设、人工调整和指标口径。
- 项目工作区提供五步操作指引，使用内置真实页面截图说明方案、配置、计算、调整和报告链路。
- 服务端基于统一报告模型导出七表 Excel；浏览器打印可生成 PDF。

当前仍不包含完整增值税核算、日期级账期、多场景覆盖、只读版本发布快照、Excel 输入模板和客户定制模板。

```text
amoya-project_forecast/
├── src/      完整源码、服务、测试、依赖与构建配置
├── data/     正式 SQLite 数据库
├── docs/     编号整理的设计、素材、原型、报告和计划

```

根目录第一层不再散放源码、构建配置、历史 Excel 或原型。

## 运行与构建

日常使用可直接双击根目录中与当前系统对应的启动文件。开发命令在 `src` 中执行：

```bash
cd src
pnpm install
pnpm start:local
pnpm test
pnpm build
pnpm build:legacy-singlefile
```

- 正式入口：`http://127.0.0.1:4173/`，执行启动命令后会自动打开。
- 默认数据库：`data/amoya_project_forecast.db`。
- 前端构建：`output/web/`，默认只包含 `index.html`、一个 JavaScript 文件和一个 CSS 文件。
- 兼容单文件：按需执行后生成 `output/legacy-singlefile/index.html`，不属于默认交付物。

也可以双击与当前系统对应的启动脚本：

```text
启动项目测算.cmd       Windows
启动项目测算.command   macOS
```

日常使用不需要上传或下载数据库。界面的“备份/恢复”只用于主动备份或更换数据库；服务运行时请不要用其他 SQLite 工具同时修改该文件。

## 数据模型

表命名遵循：

- `dim_`：维度
- `fact_`：事实
- `sys_`：系统
- `cfg_`：预测配置
- `snap_`：后续只读快照预留

报表基础事实坐标：

```text
项目 × Plan × 部门 × 期间 × 场景 × 指标
```

后台字段统一使用 `period`，前端统一显示“期间”。金额以十进制字符串进入 SQLite，由 Decimal.js 计算。

Schema v14 的当前配置与结果链路：

```text
cfg_model_line（参数、损益、现金公共字段 + config_json）
  + cfg_model_line_value（逐月值）
  → fact_forecast_line_value（当前方案最新原始行项目结果）
  → fact_cash_schedule_value（规则现金追溯）
  + fact_metric_adjustment（人工绝对值调整）
  → fact_metric_value（当前方案最终基础事实）
```

`sys_plan_calculation_state` 每个 Plan 只保存一条最新计算状态。“计算”替换最新原始结果并重新应用既有调整；“保存调整”直接重建最终事实并增加结果修订号，不重新执行预测公式和自动现金计划。
