# 项目测算分析工具

面向财务人员的本地项目测算与报表工具。当前实现已进入 P1A：财务人员可以维护收入、成本预测行，使用“固定月金额”或“逐月填写”完成保存、计算、分月结果和单项目报表闭环。

## 当前能力

- React + TypeScript + Vite 单包工程。
- PWA 正式运行：官方 SQLite WASM 在 Dedicated Worker 中运行，数据库通过 OPFS 自动持久化。
- 便携运行：生成真正的单个 `index.html`，使用内存 SQLite，支持导入和导出 `.sqlite3`。
- 真实部门新增、修改、启用和停用。
- 真实项目新增、修改、归档和恢复；项目是唯一主表，不维护同步副本。
- 项目保存时自动创建“公共”业务模块；场景和版本作为平台级维度统一复用。
- 2020-01 至 2035-12 的期间维度。
- 从历史交付材料提炼的 4 个项目、2 个部门和 5 类业务模块。
- 两个项目带有用于验证多维结构和报表链路的基础事实，其余项目显示无事实空状态。
- 基础指标与系统计算指标统一管理。
- 项目内“预测配置—计算表格—项目报表”三步工作区。
- 收入、成本预测行自动映射基础指标，财务人员无需维护指标编码。
- 固定月金额和逐月填写两种首批预测方式。
- 保存草稿不覆盖上一批成功结果；保存并计算生成独立计算批次。
- 行项目级分月结果保留名称、编码和分类快照，可追溯基础事实组成。
- 配置修改后，计算表格继续显示上一批成功结果并明确提示需要重新计算。
- 真实项目没有事实时显示明确空状态。
- SQLite 数据库完整备份和恢复。

当前仍不包含单价×数量、行项目公式、税率、收付款偏移、现金流生成、多场景覆盖、版本快照和 Excel 导入导出。

## 运行与构建

```bash
pnpm install
pnpm dev
pnpm test
pnpm build
pnpm build:singlefile
```

- 开发地址：`http://127.0.0.1:5173/`
- PWA 静态包：`dist/`
- 便携单文件：`dist-singlefile/index.html`

PWA/OPFS 依赖跨源隔离响应头，Vite 开发和预览环境已经配置：

```text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

部署 `dist/` 时也必须保留这两个响应头。单 HTML 不依赖 OPFS；关闭页面前必须导出数据库，否则本次修改会丢失。

## 数据模型

表命名遵循：

- `dim_`：维度
- `fact_`：事实
- `sys_`：系统
- `cfg_`：预测配置
- `snap_`：后续只读快照预留

报表基础事实坐标：

```text
项目 × 部门 × 业务模块 × 期间 × 场景 × 版本 × 指标
```

后台字段统一使用 `period`，前端统一显示“期间”。金额以十进制字符串进入 SQLite，由 Decimal.js 计算。

P1A 增加两层结果：

```text
cfg_forecast_line / cfg_forecast_value
  → fact_forecast_line_value（行项目级分月结果）
  → fact_metric_value（报表基础事实）
```

每次“保存并计算”登记在 `sys_calculation_run`。只有成功批次会替换当前项目“基准场景 + 工作版”的基础事实。
