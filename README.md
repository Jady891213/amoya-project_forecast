# 项目测算分析工具

面向财务人员的本地项目测算与报表工具。当前实现已进入 P1C：财务人员可以维护项目参数及损益、直接现金计划行，使用公式、税口径和收付款规则完成分月损益、现金计划、结果追溯和单项目报表闭环。

## 当前能力

- React + TypeScript + Vite 单包工程。
- 正式运行采用本地 TypeScript 服务：浏览器界面通过同源接口查询和保存，服务实时同步到可见的 `data/amoya_project_forecast.db`。
- `.db` 是标准 SQLite 文件，可备份、恢复并使用常规 SQLite 工具检查。
- 旧单 HTML 仅作为兼容构建保留，使用内存 SQLite，不再作为日常入口。
- 真实部门新增、修改、启用和停用。
- 真实项目新增、修改、归档和恢复；项目是唯一主表，不维护同步副本。
- 项目保存时自动创建“公共”业务模块；场景和版本作为平台级维度统一复用。
- 2020-01 至 2075-12 的期间维度。
- 从历史交付材料提炼的 4 个项目、2 个部门和 5 类业务模块。
- 四个历史项目均保存通用预测配置，并由同一计算服务生成事实和报表；不再直接灌入近似结构验证结果。
- 基础指标与系统计算指标统一管理。
- 项目内“预测配置—计算表格—项目报表”三步工作区。
- 收入、成本、收款、付款行自动映射基础指标，财务人员无需维护指标编码。
- 项目信息在项目配置页直接维护，项目中心不再提供重复编辑入口。
- 固定月金额和逐月填写两种首批预测方式。
- 项目固定参数和逐月参数，支持金额、数量、比例和普通数值。
- 行项目公式支持四则运算、参数引用、其他行项目引用和循环依赖检查。
- 损益行支持未税、含税和免税口径，公式引用统一读取标准化后的未税金额。
- 收付款规则支持当月、延后和自定义分期，以含税结算金额生成现金计划。
- 自动现金和直接现金分别追溯并汇总到统一事实。
- 现金尾期允许延伸到经营期后 36 个月，报表自动标记回收期。
- 保存草稿不覆盖上一批成功结果；保存并计算生成独立计算批次。
- 计算批次保存完整配置快照；行项目级分月结果可追溯公式与上游参数。
- 配置修改后，计算表格继续显示上一批成功结果并明确提示需要重新计算。
- 真实项目没有事实时显示明确空状态。
- SQLite 数据库完整备份和恢复。

当前仍不包含完整增值税核算、日期级账期、多场景覆盖、版本快照和 Excel 导入导出。

## 目录结构

```text
amoya-project_forecast/
├── src/      完整源码、服务、测试、依赖与构建配置
├── data/     正式 SQLite 数据库
├── docs/     编号整理的设计、素材、原型、报告和计划
├── output/   Web 构建、兼容单文件和测试输出
├── 启动项目测算.cmd
└── 启动项目测算.command
```

根目录第一层不再散放源码、构建配置、历史 Excel 或原型。

## 运行与构建

日常使用可直接双击根目录中与当前系统对应的启动文件。开发命令在 `src` 中执行：

```bash
cd src
pnpm install
pnpm start:local
pnpm test
pnpm build
pnpm build:legacy-singlefile
```

- 正式入口：`http://127.0.0.1:4173/`，执行启动命令后会自动打开。
- 默认数据库：`data/amoya_project_forecast.db`。
- 前端构建：`output/web/`，默认只包含 `index.html`、一个 JavaScript 文件和一个 CSS 文件。
- 兼容单文件：按需执行后生成 `output/legacy-singlefile/index.html`，不属于默认交付物。

也可以双击与当前系统对应的启动脚本：

```text
启动项目测算.cmd       Windows
启动项目测算.command   macOS
```

日常使用不需要上传或下载数据库。界面的“备份/恢复”只用于主动备份或更换数据库；服务运行时请不要用其他 SQLite 工具同时修改该文件。

## 数据模型

表命名遵循：

- `dim_`：维度
- `fact_`：事实
- `sys_`：系统
- `cfg_`：预测配置
- `snap_`：后续只读快照预留

报表基础事实坐标：

```text
项目 × 部门 × 业务模块 × 期间 × 场景 × 版本 × 指标
```

后台字段统一使用 `period`，前端统一显示“期间”。金额以十进制字符串进入 SQLite，由 Decimal.js 计算。

P1A～P1C 增加配置和可追溯结果：

```text
cfg_parameter / cfg_parameter_value
  + cfg_forecast_line / cfg_forecast_value
  + cfg_cash_rule / cfg_cash_rule_installment
  → fact_forecast_line_value（行项目级分月结果）
  → fact_cash_schedule_value（规则现金追溯）
  → fact_metric_value（报表基础事实）
```

每次“保存并计算”登记在 `sys_calculation_run`。只有成功批次会替换当前项目“基准场景 + 工作版”的基础事实。
