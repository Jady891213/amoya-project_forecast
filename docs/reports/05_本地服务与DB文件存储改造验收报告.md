# 本地服务与 DB 文件存储改造验收报告

验收日期：2026-08-01
范围：正式运行入口、前端数据访问、SQLite 文件持久化、界面状态和构建产物

## 一、验收结论

macOS 开发环境已完成“本地服务 + 可见 `.db` 文件”闭环：

```text
pnpm start:local
→ http://127.0.0.1:4173
→ 页面查询和保存
→ data/amoya_project_forecast.db 实时更新
→ 服务重启后恢复
```

正式页面不再依赖用户手动上传数据库，也不会在服务失联时静默切换到内存数据库。Windows 启动脚本已经提供，但仍需在客户实际 Windows 电脑上完成真机验收。

## 二、实现结果

### 2.1 服务与数据库

- 新增 TypeScript 本地服务，固定监听 `127.0.0.1:4173`。
- 服务启动时初始化和迁移 `data/amoya_project_forecast.db`。
- 查询、执行和批量事务通过同源接口完成。
- 所有写操作串行执行，成功后立即同步标准 SQLite 文件。
- 同步先写 `.tmp` 临时文件，再替换正式数据库，降低半写入风险。
- 数据库备份文件统一使用 `.db` 后缀；恢复兼容 `.db`、`.sqlite` 和 `.sqlite3`。
- API 使用启动随机令牌、同源校验、本机监听和请求体上限。

### 2.2 前端界面

- 顶栏显示“本地服务”、数据库文件名和“自动保存”。
- 左侧数据管理区域显示当前 `.db`，操作收敛为“备份/恢复”。
- 明确提示数据实时同步到本地 DB 文件。
- 服务不可用时给出 `pnpm start:local` 启动说明。
- 正式模式不显示便携模式的关闭前导出提示。

### 2.3 构建和入口

- `pnpm start:local`：构建前端、启动服务并打开浏览器。
- `scripts/启动项目测算.cmd`：Windows 双击入口。
- `scripts/启动项目测算.command`：macOS 双击入口。
- 默认 `dist/` 只保留一个 HTML、一个 JavaScript 和一个 CSS 文件。
- 旧单 HTML 改为 `pnpm build:legacy-singlefile` 按需生成，不属于默认交付物。

## 五、限制与风险

- 当前 Node 服务内部使用 SQLite WASM 管理连接，并在写入后整体导出数据库文件。对当前单用户、小型项目库足够简单可靠；当数据库明显增大或写入频率提高时，需要评估原生 `node:sqlite` 或其他驱动。
- 当前接口是现有仓储的受控 SQL 桥接，不适合作为局域网或公网服务。未来若建设中心服务，应改为领域 API 和权限模型。
- 服务运行时不支持外部 SQLite 工具并发修改正式文件；需要查看时使用只读方式或先备份。
- Windows `.cmd` 尚未在客户真实环境验证；Node.js、pnpm、杀毒软件、中文路径和系统策略仍可能带来环境差异。
