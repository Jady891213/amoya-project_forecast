# 项目测算分析工具：P1A 预测配置与计算契约

更新时间：2026-07-28  
状态：已实现并通过最终回归

## 一、范围与用户链路

P1A 只提供两种财务人员容易验证的预测方式：

- 固定月金额。
- 逐月填写。

允许建立收入、成本、收款、付款行项目。收款和付款是直接录入的资金计划，不等同于已实现账期规则。当前用户链路固定为：

```text
项目
  → 预测配置
  → 保存草稿 / 保存并计算
  → 行项目级分月结果
  → 损益、现金流基础事实
  → 计算表格
  → 项目报表
```

P1A 不包含单价×数量、比例、行项目引用、税率、从账期规则自动生成现金流、多场景覆盖、版本快照或 Excel。

## 二、Schema v3/v4

| 表 | 用途 |
|---|---|
| `cfg_forecast_line` | 预测行项目定义、排序和预测方式配置 |
| `cfg_forecast_value` | 逐月填写的原始金额 |
| `sys_calculation_run` | 计算批次、配置摘要、状态和问题 |
| `fact_forecast_line_value` | 行项目级分月计算结果及行项目快照 |
| `fact_metric_value` | 增加 `calculation_run_id`，继续保存报表基础事实 |

Schema v4 扩展 `cfg_forecast_line` 和 `fact_forecast_line_value` 的分类约束，使同一套固定月金额、逐月填写能力可用于现金流入和现金流出。没有另建项目专用现金表。

行项目计算结果粒度：

```text
项目 × 行项目 × 部门 × 期间
× 场景 × 版本 × 基础指标 × 计算批次
```

报表事实粒度仍沿用 P0：

```text
项目 × 部门 × 期间 × 场景 × 版本 × 指标
```

`fact_forecast_line_value` 保存行项目编码、名称和分类的批次快照。之后修改、重命名或删除配置行，不得使上一批成功结果失去来源说明。

## 三、行项目规则

每个预测行包含：

- 系统内部 ID。
- 系统生成的稳定编码，例如 `LINE-001`。
- 行项目名称。
- 系统分类：收入、成本、收款或付款。
- 预测方式。
- 生效开始、结束期间。
- 固定月金额或逐月金额。
- 假设说明和表格顺序。

收入、成本、收款、付款依次自动映射 `revenue`、`cost`、`cash_inflow`、`cash_outflow`。财务用户不维护指标编码。

### 固定月金额

- 每月金额必须是有效十进制数字。
- 仅在生效开始、结束期间内展开。
- 周期合计为月金额乘以生效月数。

### 逐月填写

- 只允许填写项目预测周期内的期间。
- 生效期间内空白月份按 0 计算，并返回警告。
- 生效期间外的值不参与结果。

两种方式都允许负数，用于退款、冲销和调整；系统给出提醒但不阻止计算。

## 四、保存、计算与结果替换

### 保存草稿

- 持久化行项目与逐月值。
- 不覆盖上一批成功结果。
- 通过确定性配置摘要判断“当前配置是否与结果一致”。

### 保存并计算

1. 保存当前配置。
2. 校验项目状态、行项目、期间和金额。
3. 创建计算批次。
4. 展开固定月金额或逐月填写。
5. 生成行项目级分月结果。
6. 按模块、期间、基础指标汇总。
7. 成功时替换当前项目“基准场景 + 工作版”的 `fact_metric_value`。
8. 项目报表查询时继续由系统指标引擎计算毛利、毛利率。

配置保存与计算结果提交分为两个明确边界：无效配置仍需保留供用户修改；计算结果、成功批次和基础事实必须在同一个 SQLite 事务中生效。任何结果写入失败都不得破坏上一批成功结果。

首次真实计算会替换当前项目工作版下的上一批基础事实，不混合汇总，也不影响其他项目。

## 五、计算问题

`CalculationIssue` 必须提供：

- 严重程度：错误或警告。
- 行项目 ID。
- 字段。
- 期间（适用时）。
- 可直接理解的说明。

错误阻止结果提交；警告不阻止计算。至少校验：

- 项目存在且处于“测算中”。
- 行项目名称不为空。
- 生效期间位于项目周期内，结束不早于开始。
- 金额是有效十进制数字。
- 至少有一条有效损益或现金流行。

## 六、页面契约

预测配置页使用左表右表单的挤压式布局，不使用遮罩：

- 左表回显分类、名称、模块、方式、摘要、期间、合计和完整性。
- 右侧维护通用字段和方式专属配置。
- 工具栏提供新增收入项、成本项、收款项、付款项、保存草稿、保存并计算。
- 项目信息在同一配置页直接编辑，不再从项目中心弹出重复编辑窗口。

计算表格只读显示：

- 批次号和最后计算时间。
- 配置是否与结果一致。
- 行项目级分月组成。
- 收入、成本、毛利和毛利率。
- 当前固定的全局基准场景、工作版。

项目报表继续只读取 `fact_metric_value`。直接维护收款、付款行时可以生成现金流事实；项目没有现金计划时必须显示阶段说明，不得用全 0 表格冒充结果。税率和账期驱动的自动现金流仍属于 P1C。

## 七、后续边界

- P1B：业务参数、单价×数量、比例、行项目引用和循环依赖检查。
- P1C：税率、含税/不含税、收付款偏移和现金流。
- P1D：统一 Excel、CSV、图表报告和项目文件交换。
- P2：多场景覆盖、版本快照和场景比较。
