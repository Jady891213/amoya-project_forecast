# Plan 方案与跨项目项目报表契约

状态：已实施  
适用数据结构：Schema v13

## 1. 核心结论

Schema v13 将原先“项目版本”校正为项目下属的测算方案 `Plan`，暂时移除业务 Version 概念。

```text
Project
└── Plan
    ├── 起止期间
    ├── 参数、预测项、税与现金规则
    ├── Calculation Run
    └── Fact
```

- `Project` 只维护项目编码、项目名称、申报部门和项目状态。
- `Plan` 表示项目内相互排斥的可选测算方案，拥有独立期间、配置、修订号、批次和事实。
- `Scenario` 仍固定为全局“基准场景”。
- `Run` 只是某个 Plan 的一次计算执行，不是业务方案或版本。
- 全局指标定义继续复用，不按 Plan 复制。

## 2. 数据结构

`dim_plan` 的关键字段为：

```text
id + project_id + name + start_period + end_period
+ is_default + status + sort_order + draft_revision
```

约束：

- Plan ID 全局唯一，同项目名称唯一。
- 每个项目必须且只能有一个有效默认 Plan。
- 最后一个有效 Plan 不允许归档，默认 Plan 归档前必须先切换默认方案。
- 配置、覆盖、批次、行项目结果、现金追溯和基础事实均保存 `project_id + plan_id`。
- 组合外键保证 Plan 必须属于对应项目，不能生成非法 Project × Plan 组合。

正式事实坐标为：

```text
项目 × Plan × 申报部门 × 期间 × 场景 × 指标
```

Schema v13 不再包含 `dim_version`、`rel_project_version` 或业务 `version_id`。

## 3. 项目工作区

- 新建项目自动建立“默认方案”。
- 方案支持空白新建、复制当前方案、重命名、设为默认、归档和恢复。
- 项目名称、项目编码和申报部门由所有 Plan 共享；起止期间和全部测算内容按 Plan 隔离。
- 项目配置、计算底表、项目报告和 Excel 导出统一使用 `planId`。
- 保存只保存当前 Plan 草稿；计算只替换当前 Plan 的成功事实，不影响同项目其他 Plan。

## 4. 跨项目项目报表

根目录“项目报表”读取成功计算事实，采用 `POV + 行轴 + 列轴`：

- 可用维度：项目、方案、申报部门、期间、指标。
- 场景固定在 POV 为“基准场景”。
- 每个维度必须且只能出现在 POV、行轴或列轴之一。
- POV 单选；项目和部门允许“全部”，方案不允许“全部方案”。
- 行列轴均支持多个维度、调整位置和成员多选。
- 期间支持连续起止范围，并允许取消个别月份。
- Plan 按项目分组选择；Plan 不带 Project 轴时，标签同时显示所属项目。
- Plan 位于行列时始终分开返回，不跨 Plan 相加。
- 基础指标按合法坐标求和；毛利、毛利率、净现金流和累计现金流在聚合后重算。
- 无事实组合显示“—”，不伪造零值。

结果表使用真实多级行列表头，支持单元格点击、拖拽框选、Shift 扩展、行列标题选区和 TSV 复制到 Excel；当前只读。

## 5. 兼容边界

- v12 开发库在重建前单独备份；本轮不提供 v12 自动迁移。
- 导入旧库时明确提示结构过旧，不静默转换。
- Schema v12 文档和验收报告保留为历史阶段记录，本文件是当前有效契约。
- 正式只读发布快照如果未来出现，再重新引入 Version 或 Snapshot，不能复用 Plan 含义。
