# P1B 项目参数与行项目公式契约

更新时间：2026-07-28
状态：已实现并通过最终回归

## 一、范围

P1B 在 P1A 的固定月金额和逐月填写基础上增加：

- 项目固定参数。
- 项目逐月参数。
- 金额、数量、比例和普通数值四类参数。
- 参数与行项目的四则运算。
- 行项目依赖排序和循环引用检查。
- 计算批次配置快照。

不包含税规则、账期、多场景、版本快照、Excel 或自由脚本。

## 二、Schema v5

新增：

| 表 | 用途 |
|---|---|
| `cfg_parameter` | 项目参数定义、稳定编码、类型、单位和固定值 |
| `cfg_parameter_value` | 逐月参数值 |

调整：

- `cfg_forecast_line.forecast_method` 增加 `formula`。
- `cfg_forecast_line.formula_expression_text` 保存规范公式。
- `sys_calculation_run.config_snapshot_json` 保存不可变配置快照。

参数编码由系统按项目生成，例如 `PAR-001`；行项目继续使用 `LINE-001`。编码保存后不可修改。

## 三、参数规则

- 固定参数在项目全部期间使用同一个值。
- 逐月参数按公式当前期间读取。
- 逐月参数在被公式引用的期间缺失时返回错误，不按零处理。
- 比例界面以百分数录入，数据库按小数保存。
- 被公式引用的参数不允许删除。
- 参数属于当前项目，不进入 `dim_metric`。

## 四、公式语法

支持：

```text
+  -  *  /
( )
负数
百分数字面量，例如 20%
PARAM("PAR-001")
LINE("LINE-001")
```

示例：

```text
PARAM("PAR-001") * PARAM("PAR-002")
LINE("LINE-001") * PARAM("PAR-003")
(LINE("LINE-001") - LINE("LINE-002")) * 30%
```

规则：

- 公式按标准乘除优先于加减。
- 行项目引用读取上游行当前期间结果。
- 上游行不在生效期间时按零处理。
- 缺失引用、缺失参数值、除零、语法错误和循环引用阻止计算。
- 不支持 JavaScript、SQL、自定义函数或访问系统环境。

## 五、保存和计算

配置摘要必须包含：

- 参数定义。
- 固定值和逐月值。
- 行项目定义。
- 固定月金额、逐月值和公式。

参数或公式变化后，`config_hash` 必须变化并把上一批结果标记为过期。

成功计算时：

1. 解析全部公式。
2. 建立依赖图。
3. 先计算非公式行，再按依赖顺序计算公式行。
4. 写入 `fact_forecast_line_value`。
5. 汇总写入 `fact_metric_value`。
6. 保存完整 `config_snapshot_json`。

## 六、页面契约

预测配置包含“预测行项目”和“项目参数”两个二级页签，均使用左表右侧挤压式编辑面板。

公式编辑必须提供：

- 中文公式说明。
- 参数和行项目引用入口。
- 运算符。
- “单价 × 数量”和成本“按收入比例”快捷方案；单价、数量和比例直接维护在当前预测行，不要求用户预先创建业务参数。
- 引用来源。
- 分月试算与错误提示。

计算表格必须显示公式来源、依赖项和当前批次配置快照。

快捷方案只简化录入，不新增计算引擎：行内配置保存于 `config_json`，保存时生成受限公式表达式，并与自定义公式共同经过 Decimal.js、依赖检查、计算批次和事实汇总链路。逐月变化或更复杂的驱动关系仍使用业务参数与自定义公式。
