# Schema v14：事实调整与最新结果契约

## 1. 核心链路

```text
项目参数与预测项配置
→ 点击计算
→ 最新原始行项目底稿与现金计划
→ 人工底稿调整
→ 保存调整
→ 最终基础事实
→ 派生指标、项目报告、项目报表与 Excel
```

配置、原始结果、人工调整和最终事实是四种不同性质的数据，禁止相互回写。

## 2. 数据职责

- `cfg_model_line`、`cfg_model_line_value`：当前 Plan 的参数与预测项配置。
- `fact_forecast_line_value`：当前 Plan 最新一次成功计算的原始行项目分月结果。
- `fact_cash_schedule_value`：当前 Plan 最新一次成功计算的自动或直接现金计划。
- `fact_metric_adjustment`：底稿叶子单元格的人工最终绝对值，唯一坐标为项目、Plan、预测项和期间。
- `fact_metric_value`：应用人工调整后的最终基础事实，供报告、项目报表和 Excel 使用。
- `sys_plan_calculation_state`：每个 Plan 一条最新计算状态，不承担历史版本保存。

数据库不再包含 `sys_calculation_run`、`cfg_forecast_override` 和 `dim_plan.is_default`。

## 3. 计算与调整边界

点击“计算”时：

1. 保存尚未保存的项目配置。
2. 编译参数、预测公式、税口径和收付款规则。
3. 成功后事务化替换当前 Plan 的原始行项目事实和现金计划。
4. 重新应用已有人工调整，重建最终基础事实。
5. 失败只更新计算状态和问题，不覆盖上一版成功结果。

点击“保存调整”时：

1. 校验目标是当前 Plan 可编辑的原始叶子单元格。
2. 保存整批人工调整并校验结果修订号。
3. 直接重建最终基础事实和派生指标。
4. 不重新执行预测项公式、税换算或自动现金计划。

收入、成本调整会改变毛利和毛利率，但不会反向改变引用该行的其他预测项，也不会重新生成该行的自动收付款。直接收款、付款调整会影响净现金流和累计现金流。规则生成现金保持只读。

## 4. Plan 与状态

- 每个项目至少保留一个有效 Plan。
- 不设置默认 Plan；未指定 `planId` 时按 `sort_order + created_at` 选择第一条有效 Plan。
- 新项目自动创建“方案 1”。
- 前台状态只表达未计算、结果过期、计算成功、计算失败和调整未保存，不展示 Run 编号。

## 5. 页面约束

- 项目配置只读取和保存配置，不加载人工调整。
- 计算底稿显示原始值、调整值、差额、说明和修改时间；保存调整后结果立即生效。
- 项目报告、跨项目项目报表和 Excel 只读取当前 Plan 的最终事实。
- 操作指引为只读内置资源，不读写数据库。
