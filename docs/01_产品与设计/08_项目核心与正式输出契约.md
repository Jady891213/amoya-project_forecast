# 项目核心与正式输出契约

更新时间：2026-08-01  
适用版本：Schema v7

## 一、目标与边界

本阶段把应用从“前端 SQL 桥接和分散保存”收敛为正式本地项目应用：

```text
项目聚合草稿
  → 语义化 API
  → 统一保存和计算
  → 可编辑计算工作表
  → 成功计算批次
  → 页面报告、Excel 和打印报告
```

继续保持本地单用户、TypeScript 服务和标准 SQLite `.db` 文件。不建设登录、多人协作、审批、云服务、多场景覆盖、版本快照、跨项目分析或工具内置 AI。

## 二、正式分层

```text
src/app     React 页面、URL 路由、语义 API Client、FinancialGrid
src/server  HTTP 路由、应用服务、仓储、SQLite 和 Excel 输出
src/shared  API 契约、领域类型、公式及确定性计算引擎
```

约束：

- 正式页面不得发送、拼接或理解 SQL。
- SQL、事务、仓储和数据库文件同步只存在于服务端。
- 前后端共用 `src/shared` 的请求、响应和领域类型。
- 旧便携单 HTML 仍可按需构建，但其数据库客户端和旧页面只属于兼容层。
- 正式服务继续绑定 `127.0.0.1`，保留随机令牌、同源检查、请求体上限和数据库即时落盘。

## 三、项目工作区契约

### 0. 统一应用外壳

- 不设置全局顶部标题栏。
- 左侧导航在平台页面和项目详情中始终保留，并支持折叠/展开。
- 产品标识与折叠按钮位于侧栏顶部；SQLite 状态、备份和恢复操作位于侧栏底部。
- 进入项目只替换右侧内容，不切换为另一套全屏外壳。
- 项目中心、主数据、指标管理和项目详情的右侧标题栏统一为 64px；平台根页面不显示面包屑，项目详情显示“项目管理—项目—当前页面”面包屑。
- 项目入口记录最近一次项目详情及页签。用户从项目详情切到主数据或指标管理后再次点击项目入口，应恢复原项目状态；明确返回项目中心时，记录更新为项目列表。

### 1. URL

```text
/projects
/projects?view=archived
/projects/new/config
/projects/:id/config
/projects/:id/calculation
/projects/:id/report
/master-data
/metrics
```

页面刷新必须保留当前项目和当前功能页。存在未保存修改时，返回项目中心、切换功能页、浏览器前进后退或关闭页面均需提示。

### 2. 聚合草稿

`ProjectWorkspaceDraft` 一次包含：

- 项目信息与业务模块。
- 项目参数及逐月值。
- 损益预测行与直接现金行。
- 税口径和收付款规则。
- 计算工作表期间覆盖值。

项目配置页采用上下结构：项目信息与业务模块表单固定在上方；测算配置整体位于表单下方。测算配置内部左侧紧凑切换“损益预测、直接现金、项目参数”，右侧展示对应明细表格，选中明细后才在表格右侧挤压显示编辑表单，不使用覆盖内容的大侧栏或蒙层。

顶部只保留统一的“保存、计算、更多”操作：

- 保存：保存整个项目草稿，修订号递增，不生成计算批次。
- 计算：存在未保存修改时先保存，再使用返回的修订号计算。
- 更多：归档和恢复等低频动作。

项目状态统一表达为：有未保存修改、已保存等待计算、结果与配置一致、结果需要重新计算、计算失败但上次结果仍有效。

### 3. 乐观修订

`dim_project.draft_revision` 是项目聚合草稿修订号。保存请求必须携带 `expectedRevision`；不一致返回 HTTP 409 和当前修订号，禁止静默覆盖其他页面的修改。

项目名称、客户、负责人和备注不进入计算输入哈希；项目期间、部门、模块、参数、公式、税、收付款规则和期间覆盖值进入完整输入哈希。

## 四、语义化 API

正式页面使用：

```text
GET    /api/bootstrap
GET    /api/projects
POST   /api/projects
GET    /api/projects/:id/workspace
PUT    /api/projects/:id/workspace
POST   /api/projects/:id/calculations
GET    /api/projects/:id/calculations/latest
GET    /api/projects/:id/calculations/:runId
POST   /api/projects/:id/archive
POST   /api/projects/:id/restore
GET    /api/departments
POST   /api/departments
PUT    /api/departments/:id
GET    /api/metrics
GET    /api/projects/:id/report
GET    /api/projects/:id/export.xlsx
GET    /api/database/backup
POST   /api/database/restore
```

原始 `/api/database/query`、`execute`、`batch` 不再提供。统一错误返回 `code`、`message`、可选字段定位和可选当前修订号。

`/master-data` 保持“项目、部门、业务模块、期间、场景、版本”六类主数据工作台：项目和业务模块由项目工作区维护并在此只读查看，期间、场景和版本为系统维度，部门通过部门语义接口维护。语义 API 重构不得把主数据页面缩减成单一部门表，也不得让页面重新直接查询 SQLite。

## 五、Schema v7 与期间覆盖

Schema v7 新增：

- `dim_project.draft_revision`。
- `sys_calculation_run.draft_revision`。
- `sys_calculation_run.project_snapshot_json`。
- `cfg_forecast_override`。

覆盖值的唯一坐标为“项目 + 预测行 + 期间”。收入和成本覆盖值表示未税标准结果；直接现金覆盖值表示实际收付款金额。

覆盖不会修改原公式、固定月金额或逐月配置。计算时：

1. 编译原配置结果。
2. 使用覆盖值替换对应叶子结果。
3. 下游公式读取覆盖后的上游结果。
4. 重新生成税额、含税结算额、自动收付款计划和系统指标。
5. 在成功批次快照中保留覆盖前值、覆盖值、说明和修改时间。

清除覆盖后，下一次计算恢复原预测方式结果。公式本身存在错误时，覆盖不得绕过公式校验。

## 六、FinancialGrid

财务表格默认按两位小数和千分位展示，并在表格上方提供元、千元、万元，小数位数、千分位和负数样式切换；显示格式不改变数据库值、计算精度或复制原值。鼠标拖拽与 Shift 均可形成矩形选区。

内部财务表格组件统一服务于逐月输入、计算工作表和只读报表，支持：

- 鼠标矩形框选、Shift 扩展、整行、整列和全表选择。
- 方向键、Tab、Enter、F2 和直接键入编辑。
- TSV 复制以及从 Excel 粘贴矩形区域。
- Delete/Backspace 清空。
- `Ctrl/Cmd+D` 向下填充，`Ctrl/Cmd+R` 向右填充。
- 50 步撤销/重做。
- 千分位、负数和括号负数解析。
- 整个粘贴或填充区域原子校验；遇到非法值或只读单元格时全部取消。

计算工作表只允许编辑收入、成本、直接收款和直接付款叶子行；汇总、毛利、毛利率、现金流派生指标和周期指标始终只读。

## 七、统一报告与输出

`ProjectReportDto` 是页面报告、打印和 Excel 的唯一报告模型，只读取成功计算批次，包含：

- 项目信息快照、批次号和草稿修订号。
- 分月损益、分月现金流、行项目明细和收付款追溯。
- 关键参数、人工覆盖、指标公式和数据来源。
- 确定性测算摘要、风险提示和“是否落后当前草稿”。
- 可切换的历史成功批次。

页面报告使用本地打包 ECharts，不访问 CDN；浏览器打印样式生成打印/PDF 版。Excel 由服务端生成统一七表模板：项目信息、测算假设、分月损益、分月现金流、行项目计算明细、收付款追溯、指标和公式说明。

客户特殊 Excel 版式仍属于平台外调整，不为不同客户维护平行模板。

## 八、冻结结论

- 正式页面只调用业务语义接口。
- 项目是一个聚合草稿，项目信息与预测配置不再分散保存。
- 保存和计算是两个动作；计算可自动先保存。
- 期间覆盖是可追溯的项目草稿内容，不改变模型定义。
- 页面、打印和 Excel 必须使用同一个成功批次报告模型。
- `.db` 文件仍是唯一正式持久化载体。
