# 业务建模与多维数据模型

更新时间：2026-07-28
状态：当前业务与技术架构基线

## 一、总体结构

产品采用四层确定性链路：

```text
业务建模层
→ 模型编译层
→ 多维事实层
→ 报表查询层
```

- 财务用户在业务建模层维护项目参数和预测行项目。
- 模型编译层解析预测方式、公式、税口径和收付款规则，展开分月损益与现金计划。
- 多维事实层保存基础指标，不回写毛利等系统计算指标。
- 报表查询层按项目、模块和期间聚合事实并计算派生指标。

工具内不调用 AI，也不允许任意 JavaScript 或 SQL 公式。同一配置必须生成同一结果。

## 二、业务建模层

P1C 支持：

- 固定月金额。
- 逐月填写。
- 固定项目参数。
- 逐月项目参数。
- 参数四则运算。
- 引用其他行项目。
- 含税、未税和免税金额口径。
- 当月、延后和自定义分期收付款。
- 独立的直接收款、付款计划。

收入、成本、收款和付款行分别映射到四类基础指标。参数属于项目，不进入全局指标维度。

完整增值税核算、日期级账期、场景覆盖和版本快照属于后续阶段。

## 三、模型编译层

编译器负责：

1. 校验项目、期间和业务模块坐标。
2. 解析公式并建立依赖图。
3. 检查缺失引用、缺失期间、除零和循环引用。
4. 按依赖顺序逐月计算。
5. 将损益行标准化为未税金额，并还原含税结算额。
6. 按规则生成可追溯现金计划。
7. 生成行项目级分月结果。
8. 汇总直接现金与规则现金，按基础指标和多维坐标写入事实。
9. 记录计算批次、问题和不可变配置快照。

公式使用稳定编码存储，界面使用中文名称解释。金额和参数使用十进制字符串保存，由 Decimal.js 计算。

## 四、多维事实层

冻结坐标：

```text
项目
× 部门
× 业务模块
× 期间
× 场景
× 版本
× 指标
```

基础事实：

- 收入。
- 成本。
- 现金流入。
- 现金流出。

系统查询时计算：

- 毛利。
- 毛利率。
- 净现金流。
- 累计现金流。
- 最大垫资。
- 现金转正期间。

规则现金另以来源行、业务发生期间和结算期间为坐标保存在 `fact_cash_schedule_value`，用于解释统一现金事实的组成。

## 五、存储与运行

- SQLite WASM 在 Dedicated Worker 中运行。
- PWA 通过 OPFS 持久化固定数据库文件。
- 单 HTML 使用内存 SQLite，通过 `.sqlite3` 导入导出交换数据。
- Schema 通过 `sys_schema_migration` 顺序升级。
- 页面只能调用仓储和服务，不直接拼装 SQL 或复制计算公式。

## 六、结果一致性

配置保存和结果提交是两个边界：

- 无效草稿可以保存，便于继续修改。
- 成功批次、行项目结果和基础事实必须事务化生效。
- 失败批次保留问题说明，不得破坏上一批成功结果。
- 项目报表只读取成功批次形成的基础事实。
