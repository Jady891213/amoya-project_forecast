# 项目测算分析工具：P0 SQLite 数据契约

更新时间：2026-07-28  
状态：已实现并冻结；P1A 仅通过 Schema v3 扩展配置与计算批次，不改变本契约

## 一、运行与存储边界

```text
PWA
  → Dedicated Worker
  → SQLite WASM
  → OPFS 固定数据库文件

便携单 HTML
  → 主线程内存 SQLite
  → 手动导入/导出 .sqlite3
```

IndexedDB 已退出当前运行库；旧构建和旧 Origin 下的数据不自动删除或迁移。PWA 是持久化验收环境，单 HTML 是便携体验与数据库文件交换环境。

页面、报表服务和指标引擎只能通过仓储接口读写数据，不得直接调用 SQLite：

- `ProjectRepository`
- `DepartmentRepository`
- `DimensionRepository`
- `MetricRepository`
- `FactRepository`
- `MetadataRepository`
- `DatabaseClient.batch()` 事务边界

## 二、表与字段命名

- 维度表：`dim_`
- 事实表：`fact_`
- 系统表：`sys_`
- 后续预测配置表：`cfg_`
- 后续快照表：`snap_`
- SQLite 字段统一使用小写下划线。
- 后台统一使用 `period`；前端统一显示“期间”。

P0 冻结表：

| 表 | 用途 |
|---|---|
| `dim_project` | 项目唯一主表和唯一数据源 |
| `dim_department` | 部门主数据 |
| `dim_business_module` | 项目级业务模块 |
| `dim_period` | 期间维度 |
| `dim_scenario` | 平台级场景维度 |
| `dim_version` | 平台级版本维度 |
| `dim_metric` | 基础指标和系统计算指标统一维度 |
| `fact_metric_value` | 只保存基础指标数值 |
| `sys_app_metadata` | 应用与初始化数据集状态 |
| `sys_schema_migration` | SQL 迁移记录 |

## 三、维度规则

### 项目与部门

- 项目只使用一张 `dim_project`，不建立“填报项目/维度项目”两套副本。
- 项目名称、部门和开始期间必填；项目编码填写时唯一。
- 项目周期限制 1～36 个月；状态只有“测算中、已归档”。
- 用户项目不提供物理删除。
- 不参与查询的扩展属性可放 `attributes_json`；可筛选字段必须独立建列。
- 部门编码唯一，用户部门支持新增、修改、启用和停用。
- 真实项目只能引用用户维护的部门。

### 业务模块、期间、场景与版本

- 业务模块属于单个项目，同一项目内编码唯一。
- 每个项目自动存在编码为 `PUBLIC` 的“公共”模块。
- `dim_period.period` 主键格式固定为 `YYYY-MM`；初始化 2020-01 至 2035-12。
- P0 全平台只有一个系统内置“基准场景”，所有项目共同引用。
- P0 全平台只有一个系统内置、可变的“工作版”，所有项目共同引用。
- 新建项目不复制场景或版本；场景、版本与项目只在事实坐标上相交。
- P0 不创建历史版本快照。

## 四、指标与事实

`dim_metric` 统一保存：

- 基础指标：收入、成本、现金流入、现金流出。
- 系统计算指标：毛利、毛利率、净现金流、累计现金流。

系统计算指标只允许系统维护，项目特有公式未来进入 `cfg_` 预测配置，不进入全局指标维度。

事实唯一坐标：

```text
project_id
+ department_id
+ business_module_id
+ period
+ scenario_id
+ version_id
+ metric_code
```

`fact_metric_value` 只保存基础指标。`value_text` 使用规范化十进制字符串，计算由 Decimal.js 执行；毛利等结果不回写事实表。

| 指标 | 表达式 | 期间汇总 |
|---|---|---|
| 毛利 | `revenue - cost` | 求和 |
| 毛利率 | `gross_profit / revenue` | 汇总后重算 |
| 净现金流 | `cash_inflow - cash_outflow` | 求和 |
| 累计现金流 | `previous(cumulative_cash_flow) + net_cash_flow` | 期末值 |

周期级报告结果：

- 最大垫资：累计现金流最低负值的绝对值，否则为 0。
- 现金转正期间：曾经为负后首次恢复到非负的期间。
- 始终非负：显示“无需垫资”。
- 周期内未恢复：显示“预测期内未转正”。
- 收入为 0：毛利率显示“—”。

## 五、历史项目与结构验证事实

- 初始化唯一来源是 `src/mocks/p0ReferenceDataset.ts`。
- 项目、部门与业务模块从历史 Excel 和已确认原型中提炼，统一使用 `dataset_id = p0-reference-v2`。
- 当前初始化 4 个历史项目：河北联通云游戏 + 超高清、重庆移动中屏、河北有线互联网电视、百视通 CTV 程序化广告能力建设。
- 部门采用已确认原型中的“互联网电视事业部、广告业务部”；历史 Excel 未提供可靠组织归属，不继续推断更多部门。
- 两个项目附带结构验证事实，仅用于打通 P0 多维查询与报表；基础事实仍集中在同一初始化文件中。
- 初始化幂等；内部清理使用同一 SQLite 事务，不影响后续用户数据、系统指标、期间、全局场景和全局版本。
- 用户新建项目不生成事实数据。

## 六、备份恢复

- 导出完整 `.sqlite3` 文件。
- 导入前校验 SQLite 文件头。
- 导入数据库必须包含受支持的 `sys_schema_migration`。
- 恢复后重新执行幂等迁移和系统指标种子。
- 便携模式持续显示“不自动持久化”提示。

## 七、P0 页面边界

- 主数据管理只显示：项目、部门、业务模块、期间、场景、版本；不显示初始化来源标签。
- 场景和版本页面不显示项目列，因为二者是平台级维度。
- 指标管理使用一张统一指标表。
- 基础事实和系统计算预览不出现在主数据页面。
- 项目工作区开放“计算表格”和“项目报表”。
- P0 交付时“预测配置”保持禁用；P1A 已在不改变本契约的前提下启用收入、成本预测配置。
- P0/P1A 均不提供跨项目分析、图表、Excel 或工具内置 AI。
