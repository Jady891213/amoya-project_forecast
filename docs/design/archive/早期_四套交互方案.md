# 项目测算分析工具：产品结构与交互方案

更新时间：2026-07-26

> 方案演进说明：本文件保留四套交互方向的阶段性结论。当前产品已收敛为“外层项目、主数据与跨项目分析—项目内预测配置、计算表格与图表报告”；场景比较并入报告，不再设置独立场景分析工作台。最新基线见 `项目测算分析工具_项目中心与预测工具台方案.md`。

## 一、已确认的产品结论

产品面向财务人员，由财务独立完成项目建立、测算、复核和导出。

第一版以分月预测为核心，同时计算损益与现金流。工具本身不包含 AI 功能；未来可以向 Agent 提供结构化计算能力，由 Agent 输入参数、获取确定性结果并在工具之外完成总结。

统一 Excel 模板是平台的标准交付物。不同项目对字体、表头、版式或客户格式的个性化调整，不纳入当前通用平台开发范围。

## 二、第一版功能范围

### 2.1 项目与版本

- 项目列表、新建项目、复制项目。
- 项目名称、客户、预测周期和测算口径。
- 默认预测周期为 12 个月，允许自定义至 36 个月。
- 基准方案版本记录和保存状态。

### 2.2 业务假设

- 维护用户数、活跃率、单价、ARPU、分成比例、CPM、码率、账期等参数。
- 参数支持固定值、逐月填写和增长规则。
- 参数可以被收入、成本和现金流公式引用。

### 2.3 分月收入与成本

- 以类似电子表格的紧凑界面维护行项目。
- 支持固定金额、单价 × 数量、比例计算和引用其他行项目组成公式。
- 公式支持参数、其他行项目、当月值、累计值和项目合计。
- 不开放任意脚本。
- 每个行项目维护税率、含税/不含税口径、生效月份和假设说明。

### 2.4 分月损益

- 分月收入、成本、毛利、毛利率和 ROI。
- 项目周期合计与年度汇总。
- 含税和不含税结果分开计算和展示。

### 2.5 分月现金流

- 损益确认与现金收付分开建模。
- 每个收入或成本行项目可配置 N 个月账期。
- 支持按比例分期收款或付款。
- 输出现金流入、现金流出、净现金流、累计现金流、最大垫资和现金转正月份。
- 第一版按月处理，不进入具体日期级资金计划。

### 2.6 场景分析

- 使用“基准方案 + 参数覆盖方案”。
- 方案可以复制、重命名和删除。
- 非基准方案只保存与基准方案不同的参数，不复制整套项目模型。
- 对比收入、成本、毛利、毛利率、最大垫资和现金转正月份。
- 对适用的线性业务模型提供盈亏平衡点和安全边际分析。

### 2.7 检查与 Excel 导出

- 检查公式错误、循环引用、缺失参数、口径不一致和未配置账期。
- 标记负现金流、异常成本比例和高资金占用等风险。
- 按统一模板导出 Excel。
- Excel 至少包括：项目概览、核心假设、分月收入、分月成本、分月损益、分月现金流、场景对比、公式与口径。

## 三、推荐的信息架构

产品不应采用一个从上到下的长表单，而应围绕一个项目工作区组织：

1. 项目设置。
2. 业务假设。
3. 分月收入与成本。
4. 损益与现金流。
5. 场景分析。
6. 检查与导出。

主工作区保持以下结构：

- 顶部：项目、版本、当前方案、保存状态和导出操作。
- 左侧：建模流程与模型检查。
- 中间：分月表格、现金流或分析结果。
- 右侧：当前行项目的公式、口径、账期和追溯信息。
- 底部：收入、成本、毛利、毛利率、最大垫资和现金转正等固定摘要。

## 四、四套原型及取舍

原型文件：`docs/prototype/archive/早期原型_四套交互探索.html`

### 方案一：专业表格工作台

- 最高屏效。
- 分月模型、现金流和公式关系可以快速切换。
- 选中行后在右侧配置公式、税率和账期。
- 最适合财务长期、高频使用。

建议作为产品的核心编辑界面。

### 方案二：分步建模向导

- 按六个步骤逐步完成模型。
- 右侧始终显示实时结果。
- 学习成本低，但高频维护效率不如表格工作台。

建议仅用于新建项目和首次初始化，不作为日常主要界面。

### 方案三：场景分析驾驶舱

- 强调基准、乐观和审慎方案对比。
- 以趋势、指标和关键参数联动为中心。
- 不适合承担完整行项目编辑。

建议作为独立的“场景分析”页面。

### 方案四：报告式审阅

- 按统一 Excel 报告章节组织结果。
- 左侧目录、中央报告、右侧检查项。
- 适合财务复核、确认异常和最终定版。

建议作为“检查与导出”页面。

## 五、推荐的最终组合

不建议从四套风格中机械选择一套覆盖全产品。建议组合为：

- 新建项目：采用方案二的分步初始化。
- 日常建模：采用方案一的专业表格工作台。
- 场景与敏感性分析：采用方案三的驾驶舱。
- 定版和 Excel 导出：采用方案四的报告式审阅。

视觉上最终统一为一套浅色、紧凑的财务后台风格。方案三原型中的深色只用于表达“分析驾驶舱”的差异，不代表最终必须使用深色主题。

## 六、当前不纳入范围

- 工具内置 AI 总结、AI 建模或 AI 修改公式。
- 业务填报、财务审批和多人协作流程。
- 复杂权限体系。
- 自由脚本公式。
- 日期级资金计划。
- 针对单个客户或项目定制 Excel 版式。
- Agent 接口的具体协议和鉴权实现；第一版先保证计算模型确定、可追溯，后续再封装。
