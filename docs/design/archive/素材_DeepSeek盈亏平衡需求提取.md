# DeepSeek 对话：盈亏平衡与多场景需求提取

更新时间：2026-07-26

来源：[DeepSeek 分享对话](https://chat.deepseek.com/share/oo3kedke6j1ncz0shw)

## 一、素材结论

分享页的核心产物是一个“业财 · 盈亏平衡与多场景对比工具”单文件原型。它补充的不是另一套完整项目测算模型，而是一个适合叠加到现有项目测算结果上的分析工作台：

1. 用统一业务量驱动多个方案。
2. 横向比较方案的收入、成本和利润表现。
3. 计算并解释盈亏平衡点与安全边际。
4. 通过图表联动快速观察参数变化的影响。

现有 `docs/prototype/archive/参考原型_轻量单页测算.html` 继续承担项目基础信息、收入/成本明细、税率和汇总指标的录入与计算；本素材补充的能力宜作为“场景与盈亏平衡分析”模块。

## 二、可吸收的功能需求

### 2.1 三方案对比

- 默认提供方案 A、方案 B、方案 C 三张并列卡片。
- 每个方案独立维护：
  - 固定成本。
  - 单位变动成本。
  - 单位价格。
- 点击卡片可切换当前分析方案。
- 修改某张卡片内的参数时，该方案自动成为当前分析方案。
- 当前方案需要有明确但不过度的选中状态。

“三方案”适合作为快速入口，后续产品化时可考虑允许复制、重命名和增减方案，不应把 A/B/C 写死为业务语义。

### 2.2 全局业务量联动

- 提供一个全局用户数/业务量输入。
- 滑块与数值输入保持双向同步。
- 业务量变化时，三个方案的结果和当前方案图表实时更新。
- “用户数”应抽象为可配置业务驱动，例如订购用户、活跃用户、广告曝光量、订单量或项目数量。

### 2.3 核心指标

当前方案至少展示：

- 盈亏平衡点（保本业务量）。
- 当前业务量下的利润。
- 安全边际率。

方案对比区宜同步展示各方案的总收入、总成本、利润和盈亏状态，使用户无需逐张点击即可比较。

### 2.4 图表

- 同一坐标系展示总收入曲线和总成本曲线。
- 在交点处标记盈亏平衡点。
- 使用垂直参考线标示保本业务量。
- Tooltip 展示业务量、收入和成本。
- 横轴范围根据当前业务量和盈亏平衡点动态调整。
- 参数变化后图表和标记实时更新。

## 三、计算口径

设：

- `Q`：当前业务量。
- `P`：单位价格。
- `V`：单位变动成本。
- `F`：固定成本。

则：

- 总收入：`Revenue = P × Q`。
- 总成本：`Cost = F + V × Q`。
- 当前利润：`Profit = Revenue - Cost`。
- 单位贡献：`Contribution = P - V`。
- 盈亏平衡业务量：`BreakEven = F ÷ Contribution`。
- 盈亏平衡收入：`BreakEvenRevenue = P × BreakEven`。
- 安全边际率：`SafetyMargin = (Q - BreakEven) ÷ Q × 100%`。

显示和计算还需统一以下细节：

- 保本业务量是否向上取整；用于业务决策时通常应向上取整，图表交点可保留精确值。
- 金额单位、百分比精度和千分位格式。
- `Q = 0` 时安全边际率不应除零。
- 固定成本为零时，需明确保本点是 0 还是从第一单位业务量起盈利。

## 四、边界与风险提示

- 当 `P <= V` 时，单位贡献不为正，模型不存在有限盈亏平衡点；显示“无法盈利”或 `∞`，并解释原因。
- 当盈亏平衡点超出图表可视范围时，仍保留指标结果，并提示交点未显示在当前区间。
- 对负数、空值、非数值、极端大数和不合理百分比进行输入校验。
- 安全边际率为负时表示当前业务量尚未达到保本点，需要使用风险色和明确文案。
- 多方案指标必须使用同一金额单位、业务量单位和含税/不含税口径，否则禁止直接比较。

## 五、与完整项目模型的衔接

DeepSeek 原型使用线性公式，适合快速分析，但历史交付物中还存在多税率、多收入项、分成基数、分月增长、阶梯成本、账期、现金流和跨项公式。因此建议增加“分析参数映射”：

- 固定成本：从项目成本项中选择固定部分。
- 单位变动成本：从随业务量变化的成本项中汇总或计算。
- 单位价格：从收入项选择，或由总收入/业务量反推。
- 业务量：选择项目中的用户数、活跃数、曝光量等驱动因子。
- 场景：复制项目基准假设后，仅覆盖需要比较的参数。

映射结果要保留来源和公式，用户能够从分析指标追溯回项目明细。

## 六、仅作参考的实现内容

以下内容来自对话中的演示代码，不作为已确认需求：

- 示例默认参数：
  - 方案 A：固定成本 50,000、单位变动成本 20、单位价格 100。
  - 方案 B：固定成本 20,000、单位变动成本 40、单位价格 100。
  - 方案 C：固定成本 100,000、单位变动成本 10、单位价格 100。
  - 当前用户数 1,000。
- 商务蓝配色和具体卡片排布。
- 通过公共 CDN 加载 ECharts。
- 单文件 HTML 的技术实现方式。

后续设计和开发应以本项目实际技术栈、离线要求、设计规范和业务口径为准。

## 七、建议验收场景

1. 调整用户数后，三个方案结果和当前方案图表同步变化。
2. 编辑方案 B 后，方案 B 自动选中，指标和图表切换到方案 B。
3. `P > V` 时，盈亏平衡点、利润和安全边际计算正确。
4. `P = V` 和 `P < V` 时，明确提示无法达到有限保本点。
5. 当前业务量低于保本点时，利润与安全边际显示为负并给出风险提示。
6. 保本点超出图表区间时，页面不报错且有解释。
7. 三个方案口径不一致时，阻止横向比较并提示统一口径。
