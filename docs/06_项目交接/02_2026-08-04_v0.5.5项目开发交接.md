## 2. 当前项目设定

- 单用户、本地 TypeScript 服务、SQLite `.db` 文件。
- 前端只调用语义 API；SQL、仓储和事务全部在 `src/server/`。
- Project 是项目主数据；Plan 是项目下属的独立测算方案；Scenario 当前固定为基准场景。
- 不存在业务 Version、默认 Plan 或前台 Run 历史。
- 每个 Plan 只保留最新原始结果、最终事实和一条计算状态。
- 跨项目项目报表读取统一最终事实，可按 Plan、部门、期间和指标组织 POV、行轴和列轴。

数据链路与表职责见[Schema v14 契约](../01_产品与设计/11_Schema_v14_事实调整与最新结果契约.md)。Plan 和项目报表基础见[Schema v13 契约](../01_产品与设计/10_Plan方案与跨项目报表契约.md)。

## 3. 最容易搞错的点

1. 项目配置、原始底稿、人工调整、最终事实不是一张表。
2. 项目配置实时预览不加载人工调整；调整不能反向改变预测公式、税额或自动现金计划。
3. “计算”替换最新原始结果；“保存调整”直接更新最终事实，不需要再次计算。
4. 报告、项目报表和 Excel 必须统一读取 `fact_metric_value`，不能在页面另算一套。
5. 未指定 Plan 时选择排序最前的有效方案，不要恢复 `is_default` 或“设为默认”。
6. 金额计算统一使用 Decimal.js 和十进制字符串，不使用 JavaScript 浮点数。
7. 当前数据库仍处开发重建阶段；修改结构前先备份，临时备份必须标记 `TMP to delete` 且不提交。
8. 兼容单 HTML 使用内存 SQLite，不等同于本地服务的自动持久化模式。

## 4. 代码入口

- `src/server/index.ts`：本地服务与数据库文件入口。
- `src/server/semanticApiRouter.ts`：语义 HTTP 路由。
- `src/server/projectWorkspaceService.ts`：项目工作区聚合服务。
- `src/server/services/calculationService.ts`：计算、调整和最终事实事务。
- `src/server/repositories/factAdjustmentRepository.ts`：人工调整仓储。
- `src/shared/calculation/`：前后端共用确定性计算引擎。
- `src/app/pages/ProjectWorkspacePage.tsx`：项目配置、计算底稿、报告和操作指引。
- `src/app/components/FinancialGrid.tsx`：统一财务表格交互底座。
- `src/server/services/reportWorkbookService.ts`：统一 Excel 输出。
