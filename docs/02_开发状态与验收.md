## 3. 验收原则

- 同一配置必须产生确定性结果。
- 页面报告、计算底稿、项目报表和 Excel 必须读取统一最终事实。
- 保存配置不写事实；计算成功才替换原始结果。
- 计算失败必须保留上一版成功事实和人工调整。
- 保存人工调整后无需再次计算，报告应立即读取新最终事实。
- 不同项目和 Plan 的配置、调整与事实不能串数据。
- 金额使用十进制字符串和 Decimal.js，避免浮点漂移。
- AI 脱敏文件不得包含真实项目、部门、行项目名称、备注或本地路径。
- 父级指标不得写入损益事实；月、季度、年度均必须从末级事实汇总，父子同时查询不得重复计数。

## 5. 后续修改要求

1. 修改业务口径前先更新 [`01_产品与数据设计.md`](01_产品与数据设计.md)。
2. 修改 Schema 前先备份 `data/amoya_project_forecast.db`。
3. 页面、Excel和项目报表不得各自复制计算逻辑。
4. 新功能递增 `src/package.json` 的第三位版本号。
5. 至少执行 `pnpm test` 与 `pnpm build`，UI 修改再做针对性浏览器检查。
6. 不从 `04_需求素材` 直接恢复已经取消的字段、旧交互或旧运行方式；确需恢复时先更新当前产品设计。
