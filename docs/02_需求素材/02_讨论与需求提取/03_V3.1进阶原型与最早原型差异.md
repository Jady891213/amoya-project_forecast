# V3.1 进阶原型与最早原型差异

更新时间：2026-08-02

## 一、对比对象与结论

本次新增素材：

- `docs/02_需求素材/03_更新需求原型/01_测算项目V3.1_进阶.html`
- 原始文件 SHA-256：`40b19955a6d68f16accfded11415a3f003529ca90b0f29dcf705426bdc39a701`

对比基线：

- `docs/03_原型/99_历史原型/01_参考原型_轻量单页测算.html`

Git 历史确认，这份历史原型最初以 `docs/prototype/index.html` 加入项目，之后只做了目录和文件名迁移，因此可以作为“最早的 index.html 原型”进行对比。

总体结论：V3.1 没有改变最早原型的单页业务模型，仍然是“填写一个项目的收入和五类成本，再生成测算结果”。主要更新集中在四个方向：

1. 总额测算扩展为可逐月填写。
2. 单一测算扩展为多个“测算模式”并列比较。
3. 只保留最近结果扩展为浏览器本地历史记录。
4. 单模式报告扩展为模式对比、融合报告和多工作表导出。

它仍然是一个基于 `localStorage` 的单 HTML 工具，没有形成平台级主数据、正式场景与版本维度、SQLite 持久化、现金流计划和可审计计算批次。因此 V3.1 更适合作为“新增交互与分析需求素材”，不能直接替代当前服务化项目的数据和计算契约。

## 二、逐项差异

| 维度 | 最早 index.html 原型 | V3.1 进阶原型 | 需求含义 |
| --- | --- | --- | --- |
| 项目数据 | 自动保存一份表单草稿和最近一次结果 | 增加历史记录面板，可保存、恢复和删除多次测算记录 | 用户希望找回以前测算过的项目，但仍不是数据库中的正式项目管理 |
| 测算模式 | 单一方案 | 可新增、复制、重命名、删除多个“模式” | 明确出现同一项目多方案比较诉求 |
| 模式共享范围 | 不适用 | 项目名称、部门、周期和单位共用；用户数、收入、成本配置按模式区分 | 本质接近“项目公共信息 + 场景覆盖配置” |
| 逐月用户数 | 只填月均用户数 | 用户数可切换为逐月录入 | 业务驱动参数需要支持期间维度 |
| 固定金额 | 只填项目总金额 | 可切换逐月金额 | 固定金额不再只能平均摊入整个项目周期 |
| 单价 × 数量 | 数量和周期为单值 | 数量可切换逐月录入 | 用户数、订购量等数量驱动可以形成月度变化曲线 |
| 批量录入 | 逐项手工填写 | 支持全部填充、区间填充、清空、从 Excel 粘贴一行、导入 CSV/TXT | 财务逐月录入效率成为明确需求 |
| 预测方式 | 固定金额、单价 × 数量 × 周期、收入比例、受限公式 | 四种方式基本保留；主要为固定金额和数量补充逐月配置 | 计算方法本身没有被重构，只增强时间颗粒度 |
| 公式能力 | 成本公式可引用收入、成本大类和非公式成本小项 | 基本沿用原限制，仍不允许公式项互相形成通用依赖链 | 不能视为完整的行项目公式引擎 |
| 税口径 | 各行填含税金额和税率，结果切换含税/不含税 | 基本不变 | 仍没有“含税录入、未税录入、免税”三种金额口径配置 |
| 分月结果 | 主要按自然年分摊展示 | 增加分月收入、成本、利润表，逐月输入按自然月落位 | 分月报表从历史 Excel 诉求进入原型主流程 |
| 模式对比 | 无 | 横向比较各模式收入、成本、利润、利润率和 ROI | 报告前置出现方案比较页 |
| 报告查看 | 单模式结果页 | 可在模式间切换，并生成融合测算报告 | 既要横向总览，也要保留单模式明细 |
| 导出 | 打印/PDF、单工作表 `.xls`、CSV | 多模式时导出融合报告及每个模式的独立工作表，并优先使用系统“另存为”能力 | 正式导出需要与模式结构保持一致 |
| 页面交互 | 表单和结果两个页签 | 保留两个页签，新增结果锚点导航、模式条、历史记录抽屉和逐月录入浮层 | 信息量明显上升，但仍是单页应用而不是项目工作台 |
| 显示精度 | 部分比例和提示使用一位小数 | 报告和对比表更多采用两位小数 | 财务展示格式需要统一，而不是由各卡片各自决定 |

## 三、V3.1 明确新增的需求

### 1. 期间化的业务输入

V3.1 把“逐月”同时用于三类信息：

- 项目用户数。
- 固定金额行。
- 单价 × 数量行中的数量。

这说明业务参数和预测行都需要能够带期间，而不是只保存项目周期总额。逐月输入还需要批量填充、区间填充、Excel 粘贴和文件导入等财务表格操作。

### 2. 同一项目的方案比较

V3.1 的“测算模式”实际承担了轻量场景功能：

- 新增空白模式。
- 复制当前模式后调整少量参数。
- 横向对比多个模式的核心指标。
- 查看每个模式的完整报告。
- 导出一份融合报告和多个模式明细。

如果进入当前平台，不建议继续建立独立的“模式”概念，应映射到已经预留的场景维度；工作版负责可编辑配置，场景负责参数或行项目覆盖，计算批次负责保存历史结果。

### 3. 多次测算的找回能力

V3.1 用 `localStorage` 历史记录解决“以前算过的内容还能再打开”。在当前平台中，这类诉求应由以下结构承担：

- 项目列表保存不同项目。
- 项目草稿保存当前配置。
- 成功计算批次保存历史结果和配置快照。
- 后续版本快照保存用户明确冻结的方案。

不建议把 V3.1 的整份页面状态 JSON 再复制一套到当前项目里。

### 4. 统一的分月报告与导出

V3.1 已经不满足于年度分摊，而是要求分月损益、方案对比和每个方案的独立报告同时出现在导出物中。这与当前项目“统一报告 DTO 驱动页面、打印和 Excel”的方向一致，未来增加多场景后应继续复用同一报告模型。

## 四、V3.1 仍未解决的内容

- 没有项目中心、部门和业务模块等真实主数据。
- 没有独立的项目、场景、版本、期间和指标维度。
- “历史记录”只是浏览器 `localStorage` 快照，不是正式版本和计算批次。
- 所有收入成本仍默认按含税金额录入，缺少明确金额口径。
- 没有收款、付款规则，也没有分月现金流、累计现金流、最大垫资和现金转正期间。
- 公式仍是页面内受限表达式，没有稳定编码、依赖图、循环依赖诊断和跨多级公式引用。
- 五大成本分类被写死，不适合作为所有项目的统一强制结构。
- “AI 分析”仍是前端规则文本，不是模型能力，正式产品应继续称为“测算摘要”或“风险提示”。
- `.xls` 仍为 XML Spreadsheet 2003 格式，不是当前项目统一的 `.xlsx` 报告。

## 五、与当前服务化项目的对应关系

### 已经覆盖或能力更完整

- 真实项目、部门、业务模块、期间、场景、版本和指标维度。
- SQLite `.db` 持久化、项目列表、归档恢复和计算批次。
- 逐月填写、固定月金额、项目参数和行项目公式。
- 公式稳定编码、参数与行项目依赖、循环依赖和除零校验。
- 含税、未税和免税口径。
- 自动收付款规则、直接现金计划、现金流和垫资指标。
- 逐月计算工作表、Excel 区域粘贴、期间覆盖和结果追溯。
- 页面报告、打印/PDF 和统一 `.xlsx` 导出。
- 历史成功计算批次切换。

### 部分覆盖，交互仍可吸收

- 当前财务表格已经支持矩形框选、Excel 区域粘贴、清空和向下/向右填充，但填充主要依赖快捷键；V3.1 的可见“全部填充、区间填充”和 CSV/TXT 导入仍可用于优化项目参数和预测行的逐月录入效率。
- V3.1 的逐月用户数属于当前“逐月项目参数”，但可补充更明确的业务模板，避免用户先理解通用参数模型。
- V3.1 的多模式融合报告结构可作为后续多场景报告的展示参考。
- 当前能够查看历史成功批次，但还不能把某个历史批次的配置恢复成当前草稿；V3.1 中“快速恢复并继续编辑”的体验，可映射为项目复制或从历史批次创建新工作版，当前不宜直接复制页面状态。

### 当前尚未实施

- 用户可维护多个真实场景。
- 复制场景、场景参数覆盖和多场景重新计算。
- 多场景横向对比表、融合报告及每场景独立 Excel 工作表。
- V3.1 使用的 ROI（毛利 ÷ 成本）尚未进入当前系统指标表和正式报告。

这些内容应进入后续多场景阶段，不应绕过现有场景、版本和计算批次模型，单独复刻 V3.1 的“测算模式”数组。

## 六、建议的吸收顺序

1. 先把 V3.1 作为需求证据归档，不修改当前冻结的数据契约。
2. 近期交互优化优先吸收逐月批量填充、区间填充和更清晰的财务数字格式。
3. 当前项目核心和正式输出稳定后，再设计“基准场景 + 场景覆盖 + 工作版/快照”的完整闭环。
4. 多场景阶段复用 V3.1 的复制、横向对比和融合报告故事线，但计算必须落入统一场景维度和计算批次。
5. 不照搬固定五大成本、全含税录入、`localStorage` 历史数组和“AI 分析”命名。
