## 一、已确定的正式运行方式

```text
启动本地服务
→ 自动打开浏览器
→ 前端通过同源接口查询和保存
→ 每次写操作立即同步 SQLite 文件
```

默认数据库：

```text
data/amoya_project_forecast.db
```

`.db` 只是文件名后缀，内部是标准 SQLite 数据库。日常使用不需要上传或下载；“备份/恢复”只用于主动备份、更换电脑或恢复历史文件。

本阶段不制作 EXE、DMG、Electron 或 Tauri 应用。旧单 HTML 仅作为兼容构建保留，不再承担正式持久化。

## 二、使用入口

开发或正式本地使用：

```bash
cd src
pnpm start:local
```

也可双击：

```text
启动项目测算.cmd       Windows
启动项目测算.command   macOS
```

启动过程会构建前端、初始化或迁移数据库、监听 `127.0.0.1:4173` 并打开浏览器。端口已由本工具占用时复用已有实例，被其他程序占用时给出明确错误。

## 三、当前技术实现

```text
React 前端
  → RemoteDatabaseClient
  → 同源 HTTP API + 启动随机令牌
  → TypeScript 本地服务
  → 串行 SQLite 操作
  → data/amoya_project_forecast.db
```

### 3.1 SQLite 驱动决策

当前服务复用项目已有的官方 `@sqlite.org/sqlite-wasm`：

- 服务启动时把 `.db` 文件载入 SQLite。
- 查询只读取当前连接。
- 执行和批量事务成功后立即导出标准 SQLite 字节，先写临时文件，再替换正式 `.db`。
- 服务关闭前再次同步并关闭连接。

这样可以兼容当前 Node.js 20 环境，不引入 `better-sqlite3` 等原生扩展，也不要求财务用户安装与系统架构绑定的可执行程序。

曾计划使用 Node.js 24 内置 `node:sqlite`，但它仍处于 Release Candidate，且会提高当前运行版本要求。本轮不采用；等其稳定并完成 Windows 真机验证后，可在不改变仓储与业务接口的前提下重新评估。

### 3.2 API 边界

当前第一版通过受控的数据库客户端桥接现有仓储，提供查询、执行、批量事务、备份和恢复接口。服务只监听本机地址，并要求页面启动时获得的随机令牌及同源请求校验。

这保证了现有 P0～P1C 业务代码可以不重写完成迁移。它不是面向网络部署的公开 API；若未来演变为中心服务或多人使用，再将通用数据库桥接收敛为项目、维度、预测和报表等领域接口。

### 3.3 文件和迁移

- `data/*.db` 和临时同步文件不提交 Git。
- 升级源码不得覆盖已有数据库。
- Schema 继续通过 `sys_schema_migration` 顺序升级。
- 可恢复旧 `.db` 或 `.sqlite3` 文件；导入前校验 SQLite 文件头和 Schema 版本。
- 服务运行时不要用其他 SQLite 工具同时修改该文件；需要检查时优先只读打开，或先使用“备份”生成副本。

## 五、构建产物收敛

默认 `pnpm build` 只生成：

```text
output/web/
├── index.html
├── assets/*.js
└── assets/*.css
```

不把数据库、源码、Node.js 或服务端代码复制进 `output/web/`。本地服务直接托管这个目录。

旧单文件只在明确需要时执行：

```bash
pnpm build:legacy-singlefile
```

输出 `output/legacy-singlefile/index.html`，不作为默认版本提交或交付。
