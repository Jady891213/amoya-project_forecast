# V3.1 增量、多版本与多维测算实施计划

状态：Schema v12 核心能力已实施，后续小增量待排期  
更新时间：2026-08-04

## 一、最终概念结论

V3.1 原型里的“模式”归入版本，不再归入场景：

```text
场景 scenario
  = 平台固定“基准场景”，当前不开放切换

版本 version
  = 同一项目下可编辑、可独立计算的测算方案
  = 当前固定 `working`、`version_1`、`version_2`、`version_3` 四个成员

计算批次 calculation run
  = 某个版本执行一次计算后形成的不可变结果记录
```

不建立第四套“模式”实体。当前“版本”承担的是可编辑方案含义，不是只读历史快照；若未来需要正式冻结、审批或发布，再另行增加快照/发布状态。

## 二、Schema v12 已实施范围

### 1. 项目版本关系

`rel_project_version` 维护项目启用的版本：

- 项目。
- 版本维度成员。
- 项目内显示名称。
- 是否默认。
- 启停状态和排序。
- 当前版本草稿修订号。

每个项目默认启用 `working` 基准方案。增加版本时只能从 `version_1`、`version_2`、`version_3` 中选择尚未启用的成员，并选择空白启用或完整复制当前配置；复制后不存在隐式继承。

### 2. 版本独立配置

以下内容按项目与版本隔离：

- 业务参数和逐月参数值。
- 收入、成本及其他现金预测项。
- 固定金额、逐月输入和公式。
- 税口径、税率和收付款规则。
- 期间覆盖值。

公式只能引用当前项目、当前版本内的参数和预测项。稳定编码可在版本间保持一致，用于识别相同业务含义。

### 3. 版本独立结果

以下数据均包含 `version_id`：

- 行项目计算结果。
- 现金计划追溯。
- 基础指标事实。
- 计算批次和配置快照。

计算只替换当前项目、当前版本、基准场景下的事实，不影响同项目其他版本。

## 三、页面闭环

### 1. 项目工作区

“项目配置—计算底表—项目报告”三页共享版本切换栏：

- 切换版本后加载该版本自己的草稿、最新成功批次和报告。
- 支持从预置成员中空白启用或复制当前配置；不支持自由新建、重命名或删除版本成员。
- 当前有未保存修改时，切换版本必须先确认；复制当前版本前自动保存当前草稿。
- 场景固定显示为“基准场景”，不出现可编辑场景入口。

### 2. 计算底表与项目报告

- 计算底表按当前版本展示最后一次成功结果。
- 报告批次列表只显示当前版本的成功批次。
- Excel 文件名包含版本名称和批次号。
- 派生指标沿用当前版本坐标，不得回落到默认版本。

## 四、全局多维事实视图

项目列表下增加“多维测算”入口，用于只读分析统一事实表。

当前支持维度：

- 项目。
- 申报部门。
- 版本。
- 期间。
- 指标。

预置视图：

1. 项目 × 版本：跨项目与同项目多版本对比。
2. 版本分月：查看所选项目不同方案的分月走势。
3. 项目分月：项目和版本置于行轴，期间和指标置于列轴。

用户可以交换行列轴、增加或移除维度，并按项目、期间和指标筛选。金额默认以万元展示，毛利率必须使用聚合后的收入和毛利重算，不能直接相加或平均。

该页面只读取成功计算写入的 `fact_metric_value`，不读取未保存草稿，也不承担配置编辑。

## 五、后续小增量

Schema v12 稳定后再按需实施：

- 版本停用和恢复的完整管理界面。
- 历史批次恢复为新版本。
- 多版本差异表和融合 Excel。
- ROI、盈亏平衡和敏感性分析模块。
- CSV/TXT 逐月输入快捷导入。
- 财务表格可见的填充、清空和撤销操作栏。

继续不进入：

- 多场景配置。
- 登录、多人协作、审核和云数据库。
- 任意 SQL、JavaScript 或脚本公式。
- 工具内置 AI。

## 六、冻结规则

- 场景保持唯一基准场景。
- 版本表示同一项目的独立可编辑测算方案。
- 计算批次表示某个版本的执行历史。
- 项目主信息在版本间共享；修改部门或期间会使所有相关结果自然落后于最新项目坐标。
- 版本配置、结果和批次必须完整隔离。
- 全局多维视图只使用成功事实，不能把实时预览混入正式分析。
