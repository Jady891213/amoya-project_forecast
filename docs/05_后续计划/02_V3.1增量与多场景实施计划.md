# V3.1 增量与多场景实施计划

状态：待实施  
计划基线：Schema v8
更新时间：2026-08-03

## 一、目标与结论

本计划把 `测算项目V3.1-进阶.html` 中相对最早原型新增的能力，吸收到当前“本地 TypeScript 服务 + SQLite `.db` + React 工作台”中，不复制其 `localStorage` 单页实现。

V3.1 的“测算模式”统一解释为场景：

```text
前端业务名称：测算方案
多维模型名称：场景 scenario
当前可编辑状态：工作版 working version
每次执行记录：计算批次 calculation run
```

场景用于同一项目不同业务假设的横向比较；版本用于同一场景不同确认时点的纵向留档。第一轮只做场景，版本继续固定为“工作版”，不同时开放版本快照。

最终链路：

```text
项目公共信息
→ 新建或复制测算方案
→ 维护该场景的参数、预测行、税和现金规则
→ 保存并计算当前场景
→ 横向比较多个场景
→ 查看单场景完整报告
→ 导出融合报告和各场景明细
```

## 二、实施范围总览

分三个里程碑交付：

### 里程碑 A：V3.1 小增量补齐

- ROI 系统计算指标。
- 财务表格可见的全部填充、区间填充和清空入口。
- CSV/TXT 逐月数据导入。
- 从历史成功批次恢复配置到当前工作版。
- 逐月项目参数的财务业务模板。

### 里程碑 B：Schema v11 与多场景配置闭环

- 场景主数据与项目启用关系。
- 每场景独立的项目参数、预测行、现金规则和期间覆盖。
- 新增、复制、重命名、停用和切换场景。
- 当前场景保存、计算和结果状态。
- 计算全部场景。

### 里程碑 C：场景比较与统一输出

- 场景核心指标比较。
- 单场景报告切换。
- 场景融合报告。
- 多工作表 Excel。
- 各场景结果新鲜度和计算批次追溯。

里程碑 A 可先独立上线；里程碑 B 完成前不开始场景比较输出。

## 三、概念和数据归属

### 1. 平台主数据

继续保留六类主数据：

- 项目。
- 部门。
- 期间。
- 场景。
- 版本。

`dim_scenario` 和 `dim_version` 仍为平台级维度，不在维度表中增加 `project_id`。

### 2. 项目公共配置

以下内容在同一项目的所有场景间共享：

- 项目编码、名称和申报部门。
- 开始期间和结束期间。

修改期间或部门等计算坐标后，项目所有场景结果均标记过期。

### 3. 场景配置

以下内容按场景隔离：

- 项目参数和逐月参数值。
- 损益预测行和直接现金行。
- 固定月金额、逐月值和公式。
- 税口径和税率。
- 收付款规则及分期明细。
- 计算工作表期间覆盖值。

场景第一次创建时支持空白新建或完整复制当前场景。复制后各场景独立修改，不建立会被基准场景继续联动的隐式继承，避免财务用户无法解释结果变化。

### 4. 版本和批次

- 每个场景只允许“工作版”编辑。
- 每次计算产生一个不可变计算批次。
- 历史批次可以查看，也可以恢复其配置快照到当前场景工作版。
- 恢复后必须重新计算，不篡改原批次。
- 正式版本冻结、版本比较和从版本派生新工作版不进入本计划。

## 四、里程碑 A：小增量补齐

### A1. ROI 指标

增加系统计算指标：

```text
ROI = 毛利 ÷ 成本
```

规则：

- 成本为 0 时显示“—”。
- 月度和项目合计均使用聚合后毛利 ÷ 聚合后成本重新计算。
- 不直接求和或平均。
- 进入指标管理、项目报告、Excel 指标说明和后续场景比较。
- ROI 不回写基础事实表。

### A2. 财务表格快捷操作

在 `FinancialGrid` 现有快捷键能力上增加可见按钮：

- 全部填充：使用当前单元格填满当前行可编辑期间。
- 区间填充：选择起止期间和填充值。
- 向下填充、向右填充。
- 清空选区。
- 撤销、重做。

继续保留：

- 鼠标矩形框选和 Shift 扩展。
- Excel TSV 复制粘贴。
- 整个区域原子校验。
- 只读单元格保护。
- 两位小数、千分位、单位和负数格式。

### A3. CSV/TXT 导入

逐月输入和逐月参数支持导入 `.csv`、`.txt`：

- 支持“期间 + 值”纵向两列。
- 支持只有数值的一行横向数据，按项目期间顺序映射。
- 忽略 UTF-8 BOM。
- 金额继续使用 Decimal 校验。
- 超出项目期间、重复期间、非法数字或只读目标时整次导入取消。
- 导入只进入当前草稿，不自动保存和计算。
- 第一轮不直接导入 `.xlsx`。

### A4. 历史批次恢复

历史成功批次增加“恢复到工作版”：

1. 读取批次 `config_snapshot_json` 和项目快照。
2. 显示将被恢复的参数、预测行和规则摘要。
3. 用户确认后写入当前场景草稿并递增修订号。
4. 当前成功结果继续保留，但状态标记为“需要重新计算”。
5. 原历史批次保持不可变。

存在未保存修改时不得静默恢复。项目公共信息默认不随批次恢复，期间不兼容时给出定位错误。

### A5. 逐月业务模板

在通用项目参数基础上提供快捷模板：

- 用户数。
- 订购量。
- 活跃用户数。
- 单价。
- 转化率或分成比例。

模板只负责预填名称、值类型、单位和固定/逐月类型，不增加新的数据库概念。

## 五、里程碑 B：Schema v11 多场景底座

### B1. 项目场景关系

新增 `cfg_project_scenario`：

- `project_id`
- `scenario_id`
- `display_name`
- `sort_order`
- `is_baseline`
- `status`
- `draft_revision`
- `latest_successful_run_id`
- `created_at`
- `updated_at`

用途：

- `dim_scenario` 保存平台场景成员。
- `cfg_project_scenario` 保存项目启用了哪些场景及项目内名称。
- 基准场景不可删除。
- 同项目只允许一个基准场景。

### B2. 场景化配置表

为以下表增加 `scenario_id`：

- `cfg_parameter`
- `cfg_parameter_value`
- `cfg_forecast_line`
- `cfg_forecast_value`
- `cfg_cash_rule`
- `cfg_cash_rule_installment`
- `cfg_forecast_override`

唯一约束调整为：

```text
项目 + 场景 + 参数编码
项目 + 场景 + 行项目编码
项目 + 场景 + 行项目 + 期间
```

内部 ID 在不同场景间不同；业务编码保持一致，使场景比较可以识别同一业务含义。公式只能解析当前项目、当前场景中的参数和行项目。

### B3. 修订和结果状态

当前 `dim_project.draft_revision` 拆分职责：

- 项目公共修订：项目信息。
- 场景草稿修订：当前场景的参数、预测行、规则和覆盖。

计算批次记录：

- `project_revision`
- `scenario_revision`
- `scenario_id`
- `version_id`

项目公共计算坐标变化后所有场景过期；只修改某个场景时不得让其他场景过期。

### B4. 开发库重建规则

- 当前仍处开发阶段，Schema v11 不承担旧开发库自动迁移。
- 数据库直接按最终场景结构重建，历史参考项目由独立素材重新初始化。
- 初始化后的全部配置归入全局基准场景，事实和计算批次使用 `baseline + working`。
- 每个初始化项目创建一条 `cfg_project_scenario` 基准关系。
- 进入真实交付和用户数据积累阶段前，再单独冻结数据库升级兼容策略。

### B5. 场景复制

复制场景在一个 SQLite 事务内完成：

1. 创建新的项目场景关系。
2. 复制参数和逐月参数值。
3. 复制预测行和逐月值。
4. 复制税口径、现金规则和分期。
5. 复制期间覆盖。
6. 重建内部 ID 引用。
7. 保留稳定业务编码和公式编码引用。
8. 不复制事实、计算批次和报告结果。

新场景创建后状态为“已保存，等待计算”。

## 七、项目工作区交互

### 1. 场景工具条

项目工作区顶部增加：

```text
测算方案：
[基准方案] [方案 A] [方案 B]

[新增方案] [复制当前] [重命名] [停用]
版本：工作版
```

前端以“测算方案”为主称呼，首次出现时辅助说明“对应多维模型中的场景”。不在同一界面同时使用“模式、方案、场景”三个名称。

### 2. 切换规则

- 切换场景时加载该场景完整工作区草稿。
- 有未保存修改时必须保存、放弃或取消切换。
- URL 保留 `scenarioId`，刷新后恢复当前场景。
- 项目配置、计算工作表和项目报告共享场景上下文。
- 版本第一轮固定显示“工作版”，不提供切换控件。

### 3. 操作语义

- 保存：保存项目公共信息和当前场景草稿。
- 计算：必要时先保存，再计算当前场景。
- 计算全部方案：依次对所有启用场景计算；单个场景失败不覆盖其上一批成功结果。
- 删除改为停用：有计算结果的场景不物理删除。

### 4. 状态展示

每个场景独立显示：

- 有未保存修改。
- 已保存，等待首次计算。
- 结果与当前配置一致。
- 结果需要重新计算。
- 计算失败，上次结果仍有效。

## 八、里程碑 C：场景报告和导出

### C1. 场景比较

项目报告增加：

```text
方案对比 | 单方案报告
```

默认比较：

- 收入。
- 成本。
- 毛利。
- 毛利率。
- ROI。
- 现金流入、现金流出。
- 最大垫资。
- 现金转正期间。

只比较有成功计算批次的场景。结果落后当前草稿时继续展示上次成功结果，但必须标记“已过期”。

### C2. 分月比较

- 支持选择一个指标查看多个场景的分月趋势。
- 经营期和回收期继续分色。
- 比例指标按各场景聚合后重新计算。
- 不对毛利率、ROI 等比例指标直接求和或平均。

### C3. 融合报告

融合报告故事线：

1. 项目公共信息和测算口径。
2. 场景列表及最后成功批次。
3. 核心指标横向比较。
4. 分月损益趋势比较。
5. 分月现金与垫资比较。
6. 各场景关键参数差异。
7. 各场景独立明细报告。
8. 指标公式和数据来源。

测算摘要继续使用确定性规则，不调用 AI。

### C4. Excel

统一 Excel 结构：

```text
项目与场景说明
场景对比
基准方案_分月损益
基准方案_分月现金流
方案A_分月损益
方案A_分月现金流
各场景行项目明细
各场景收付款追溯
指标与公式说明
```

规则：

- 工作表名去除 Excel 非法字符并处理重复名称。
- 每个场景工作表显示场景、版本、批次和修订号。
- 页面、打印和 Excel 继续读取同一个报告服务模型。
- 不为不同客户维护平行模板。

## 九、自动化测试

### 里程碑 A

- ROI、成本为零及聚合重算。
- 全部填充、区间填充、清空、撤销和只读保护。
- CSV/TXT 横向和纵向格式。
- 非法数字、重复期间和越界导入原子回滚。
- 历史批次恢复、修订递增和旧结果过期。

### 里程碑 B

- Schema v11 空库结构、历史参考项目重建及场景数据隔离。
- 现有项目全部归入基准场景且金额不变。
- 不同场景参数、行项目、规则和覆盖不串数据。
- 场景复制后稳定编码保持、内部 ID 重建。
- 公式只解析当前场景。
- 项目公共修改使全部场景过期。
- 单场景修改不影响其他场景结果状态。
- 场景计算失败保留该场景上一批成功结果。

### 里程碑 C

- 不同场景核心指标与分月数据比较正确。
- 比例指标重新计算。
- 过期和缺少结果场景正确标识。
- 多工作表 Excel 数值、工作表名和批次信息正确。
- 页面、打印和 Excel 金额一致。
- 数据库备份恢复后场景、批次和报告完整。

继续执行正式 Web、兼容单 HTML和 Windows 目标环境回归。

## 十、浏览器验收故事

以河北联通项目验证：

1. 打开基准方案并完成一次计算。
2. 复制为“包盘收入分成”。
3. 再复制为“保底订购量分成”。
4. 调整两个场景的分成参数或公式。
5. 分别保存和计算。
6. 刷新页面后保持当前项目和当前场景。
7. 在方案对比中查看收入、成本、毛利、ROI和最大垫资。
8. 切换到任一单方案报告查看完整分月结果。
9. 导出融合 Excel，核对比较表和各方案明细。
10. 修改某一场景后，只该场景显示结果过期。
11. 从其历史批次恢复配置并重新计算。

覆盖 1280×720、1366×768 和 1920×1080。
